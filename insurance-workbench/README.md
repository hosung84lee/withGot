# 보장잇

보장잇은 보험사의 **신상품 지급시스템 반영 시간을 줄이고 보험금 청구 심사를 돕는** 도구입니다. 보험사 상품·사고보장·시스템 담당자가 약관에서 지급 기준을 구조화하고, 청구 심사자가 같은 기준을 서류에 적용한 근거를 확인할 수 있도록 설계합니다.

## 프로젝트 목표

- **신상품 출시 및 개정 리드타임 단축.** 주계약·특약·별표에서 지급 사유, 면책·감액, 한도, KCD와 수술분류코드를 추출해 표준 사고보장 JSON과 계산식 초안을 생성합니다. 각 항목에 원문 위치를 붙이고, 누락·충돌·예외를 검토할 수 있도록 제안합니다. 약관 개정 시에는 변경된 기준정보와 적용 조항을 함께 비교합니다.
- **보험금 청구 AI 심사 보조.** 진단서·병리보고서 등에서 진단코드와 진단확정일, 적용 약관에 필요한 병리 소견을 읽습니다. 보장ID별로 초기암·소액암 등의 분류 후보와 특수조건을 평가하고, 결과·이유·확인할 서류 위치를 AI 태그로 남깁니다. 심사자는 원문을 보고 태그를 검토하고 지급 판단을 확정합니다. [프로젝트 상세 범위](docs/PROJECT_SCOPE.md)

## 해커톤 기술 스택

| 영역 | 기술 | 역할 |
| --- | --- | --- |
| 사용자 화면 | **Streamlit** | 약관과 청구 서류를 등록하고, 구조화 결과·AI 태그·계산 근거를 검토하는 화면 |
| 규칙과 계산 | **Python 3.12, Decimal** | 승인된 규칙으로 지급 조건을 판단하고 날짜·금액·한도를 계산 |
| 데이터 구조 | **JSON Schema, Pydantic** | 사고보장 규칙과 청구 입력을 표준화하고 검증 |
| 계산 도구 연동 | **MCP** | 보장 유형에 맞는 판정·계산 도구를 호출 |
| 테스트 | **pytest** | 전문가가 판정한 사례로 조건과 계산 결과를 검증 |

## 목표 아키텍처

문서·원문 조각·보장 규칙 버전의 필드와 승인 흐름은 [약관 문서 구조화 설계](docs/POLICY_STRUCTURING.md)를 참고합니다.

1. **AI 추출·구조화.** 약관 본문·별표의 교차 참조를 연결해 상품·약관 버전·주계약/특약·보장ID별 규칙 초안을 만듭니다. 청구 시나리오와 서류는 진단일·수술명·입원일수·진료비 등 표준 입력으로 변환합니다.
2. **업무 전문가 검토.** 지급 사유, 조건, 산식과 원문 조항을 대조해 규칙을 승인합니다. 근거가 없거나 해석이 갈리는 항목은 검토 대상으로 남깁니다.
3. **MCP 도구를 통한 판정·계산.** AI가 보장에 맞는 도구를 선택하고, 도구는 승인된 규칙에 따라 날짜·금액·한도를 계산합니다.
4. **근거 리포트.** 보장ID별 판단, 지급액, 산식, 적용 조항과 청구 서류의 근거 위치를 함께 표시합니다.

## 해커톤 구현 및 검증 목표

| 단계 | 목표 |
| --- | --- |
| 약관 구조화 | 5세대 실손 표준약관과 암 관련 정액 특약인 암진단·암수술·암입원을 표준 JSON으로 구조화하고 원문 위치 표시 |
| 지급 시연 | 암진단과 5세대 실손을 먼저 연결하고, 암수술·암입원으로 확장. 예를 들어 가입 10개월 차 위암 진단 → 위절제술 → 10일 입원 사례로 실손·정액 산출 근거 제시 |
| 검증 | AI가 제안한 면책기간 경계, 유사암 분류, 같은 날 복수 수술 사례를 전문가가 판정. 사전 정답 데이터 30건(실손 10건·정액 20건)으로 **일치율 90% 이상** 목표 |
| 추가 목표 | 기존·개정 암 특약 한 쌍의 대상 코드, 감액기간, 지급한도 변경을 조항과 함께 비교 |

상품 반영 리드타임은 약관 접수부터 검토를 마친 규칙을 등록하기까지 측정합니다. 심사 보조는 서류가 준비된 시점부터 심사 결론을 기록하기까지의 시간과 태그 정확도를 비교합니다.

## 실손 약관 비교

Streamlit에서 5세대 실손 약관 PDF를 등록하면 삼성생명 삼성 급여 실손의료비보장보험 2601(4세대, 첨부 PDF 31·65쪽)을 기준으로 급여·중증 비급여·비중증 비급여의 입원·통원 자기부담 기준을 비교합니다. 표에서 동일·변경·근거 미확인·근거 불일치 상태를 확인하고, 항목을 펼쳐 양쪽 약관의 PDF 페이지와 발췌문을 볼 수 있습니다.

‘한눈에 보는 실손 약관 비교’에서 입원 자기부담률을 그래프로 확인할 수 있습니다. 원문 대조를 완료한 삼성생명 2605 개정본에는 연간 지급한도 그래프와 보장 조건 비교도 표시합니다.

```bash
uv pip install -r apps/streamlit/requirements.txt
uv run --no-sync streamlit run apps/streamlit/policy_comparison.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

브라우저에서 http://127.0.0.1:8501 을 엽니다. 삼성생명 2605와 삼성화재 다이렉트 2605.1 텍스트 PDF 형식을 지원합니다. 표지·특약을 포함한 PDF를 사용하며, 파일 제한은 20MB·350쪽입니다. 원본은 로컬 Streamlit 세션에서 처리합니다. 기본 공제 비교는 일반 의료비에 적용합니다. 삼성생명 2605의 2026-09-23 개정본은 문서 지문이 일치할 때 원문을 대조한 상세 변경과 페이지를 별도로 표시합니다.

## 현재 React 프로토타입

- 지원 서식의 텍스트 PDF를 브라우저에서 읽고, 추출 항목과 원문 위치를 대조합니다. 가상 계약의 실손·암·종신 보장 후보를 보여줍니다.
- 약관 라이브러리와 가상 보험금 시뮬레이션을 제공합니다. 실손 계산은 한 약관 버전의 질병급여 통원 1회를 다루며, 정액 시뮬레이션은 암 진단과 종신 사망 사례를 다룹니다.
- 로컬 FastAPI와 클라우드 Worker는 가상 보장 후보 조회를 제공합니다. MCP 서버에는 상태 확인 도구가 연결돼 있습니다. 약관 전체의 자동 구조화, MCP 지급 계산 도구, 스캔 OCR, AI 심사 태그는 개발 목표입니다.

## 개인정보 보호 시연

1. 웹의 기본 화면인 ‘개인정보 보호 분석’에서 ‘가상 샘플로 시작’을 누릅니다. PDF를 직접 고를 때는 한 장씩 추가하거나 두 장을 함께 선택할 수 있습니다.
2. 두 PDF가 준비되면 자동으로 기기에서 읽습니다. 원본 위치, 치료 항목, 총액과 환자 부담액을 확인합니다. 잘못 선택한 PDF는 목록의 ‘빼기’로 제거합니다.
3. 조회할 항목과 가상 담보 상태를 선택하고 ‘전송 내용 확인’을 누릅니다.
4. 전송 항목을 확인한 뒤 ‘확인한 항목으로 서버 조회’를 누릅니다. 결과에서 조회에 쓴 급여 구분과 가상 담보 상태, 원본 위치, 다음 확인 항목을 볼 수 있습니다. ‘이 조회에서 보낸 정보’를 열면 성공한 요청의 본문을 확인할 수 있습니다.
5. ‘세션 초기화’를 누르면 앱이 보유한 원본 미리보기와 검토·조회 결과를 정리합니다.

심사 시연에서는 기본 가상 계약으로 혈액 검사와 복부 MRI를 번갈아 선택해 보장 후보와 추가 확인 상태를 비교합니다. 복부 MRI의 원본 줄을 연 뒤 결과에서 ‘이 조회에서 보낸 정보’를 펼쳐 실제 전송 내용을 확인합니다.

기본 시연은 지원 서식의 텍스트 PDF 한 쌍을 읽습니다. 파일당 제한은 10 MiB·10페이지입니다. 원본·파일명·환자번호·페이지 위치와 진료비는 브라우저 메모리에서 처리합니다. 명시적 조회 시 선택한 치료 종류·급여 구분과 조회에 필요한 가상 담보 상태만 조회 API에 전송합니다. 급여 구분이 미확인인 항목은 담보 상태 없이 확인할 수 있습니다. 조회 결과는 `synthetic-v1` 가상 규칙에 따른 후보입니다.

‘보장 지도’ 등 기존 디자인 화면에는 별도의 가상 예시가 표시됩니다. 새로 읽은 PDF의 조회 결과는 ‘개인정보 보호 분석’ 안에서 확인합니다.

## 추가 서류와 계산 기초자료

분석 첫 화면에서 기본 서류 2종과 첨부 가능한 추가 서류 4종의 목록을 볼 수 있습니다. 각 항목의 ‘샘플 PDF’ 링크로 파일을 개별 다운로드할 수 있습니다. 기본 영수증과 세부내역서를 읽은 뒤 ‘가상 추가 서류 4종 불러오기’ 또는 ‘추가 PDF 선택’을 사용합니다. 가상 추가 서류는 기본 샘플과 같은 사례번호를 사용합니다.

| 서류 | 구조화 항목과 용도 |
| --- | --- |
| 진단서 | 진단명·질병분류기호를 보장 조건 확인 근거로 보관 |
| 처방전 | 처방번호와 약 이름·투약일수를 구조화하고 약제비 영수증과 연결 |
| 납입확인서 | 같은 진료 건의 납입액을 병원 영수증과 대조 |
| 약제비 영수증 | 급여 본인부담·비급여·약국 환자 부담 합계를 대조. 처방번호가 연결되고 별도 납부를 확인한 경우에만 병원 환자 부담액에 합산 |

기초자료 JSON은 문서번호, 추출한 값과 원문 줄·페이지, 대조 상태를 담습니다. 납입확인서는 이미 기록한 진료비의 증빙으로 사용합니다. 약제비가 병원 진료비에 포함됐으면 추가 합산을 제외합니다. 같은 처방번호의 미해결 약제비 영수증이 여러 장이거나 금액 대조가 끝나지 않았으면 합계 표시를 보류합니다.

추가 서류와 기초자료는 브라우저 세션에서 처리합니다. 지원 범위는 포함된 합성 텍스트 PDF 서식이며, 표시 금액은 약관 적용 전의 환자 부담액입니다. 가상 서류 재생성은 `scripts/create-synthetic-pdfs.py --supplements`를 사용합니다.

## 기존 프로토타입 개발 환경
- Python 3.12, Node.js 24, npm, uv, Git
- Python 의존성: uv.lock / 웹 의존성: apps/web/package-lock.json
- 외부 OCR·LLM 계정 없이 기본 환경을 실행할 수 있습니다.

## 설치 및 실행
```bash
cd insurance-workbench
uv sync --locked
npm --prefix apps/web ci
bash scripts/dev.sh
```
웹: http://127.0.0.1:5173 / API 문서: http://127.0.0.1:8000/docs
두 서버는 로컬 주소로만 실행합니다. 원격 환경에서는 클라이언트의 포트 전달 기능이 필요합니다.

## 검증
```bash
bash scripts/check.sh
```
개발 서버와 API를 실행한 상태에서 개인정보 보호 브라우저 검증을 실행합니다. Windows에서는 설치된 Chrome을 사용하고, 다른 환경은 Playwright Chromium 설치가 필요합니다.

```bash
npm --prefix apps/web run test:privacy
```

API 검증은 추가 개인정보 필드 거절, 오류 응답의 입력값 비노출, 요청 크기 제한, 비용 검증을 포함합니다. 브라우저 검증은 실제 PDF 선택, 요청 본문 대조, 전송 확인 초기화, 실패·재시도·초기화, 미지원 파일 처리와 앱 저장소 검사를 포함합니다.

MCP stdio 서버:
```bash
uv run python apps/api/app/mcp_server.py
```

## 디렉터리
- apps/web: React·TypeScript·Vite
- apps/api/app: FastAPI, 향후 계산 엔진 및 문서 처리
- apps/api/tests: API·규칙 검증
- apps/cloud: 클라우드 시연용 Worker와 빌드 도구
- data/synthetic/medical-bills: 추가 합성 영수증·세부내역서와 검증 기준
- data/private: 실제 서류용 로컬 경로, Git 제외
- docs: 개발방법론·준비 체크리스트

비밀키는 .env.example을 참고해 별도로 설정합니다. 현재 기본 앱은 외부 서비스나 .env를 읽지 않습니다.
원본 PDF와 의료 서류를 저장소에 추가하지 마세요. SQLite 스키마와 마이그레이션은 데이터 모델 확정 후 추가합니다.

`apps/web/public/samples`의 기본 및 추가 서류 PDF는 직접 생성한 가상 시연 자료입니다. 샘플 재생성에는 `scripts/create-synthetic-pdfs.py`, ReportLab과 한국어 TrueType 글꼴이 필요합니다. 기본 글꼴은 Windows 맑은 고딕이며 `--font`로 변경할 수 있습니다.

PC 이전과 Windows 실행: LOCAL_SETUP.md를 참고하세요.
