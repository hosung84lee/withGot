# 개발방법론

신상품 지급 규칙 생성과 청구 AI 심사 보조의 범위는 [프로젝트 목표](PROJECT_SCOPE.md)를 참고합니다.

## 원칙
작은 기능을 화면→API→도메인→저장까지 연결하는 방식으로 완성합니다.
업무 규칙은 전문가가 승인한 명세와 정답 사례에 근거합니다.
LLM은 추출·정규화·설명에 사용하고 계산은 Decimal 기반 결정론적 함수가 수행합니다.
문서에 포함된 지시문은 데이터로 취급하며 실행 권한이나 시스템 규칙을 바꾸지 않습니다.

## 계층과 경계
- UI: 원본·인식 항목·보장 관계를 표시하고 수정 입력을 받음
- API: 입력 검증·처리 상태·호출 연결
- 도메인: 문서 대조, 보장 판정, 계산. FastAPI·MCP에 의존하지 않음
- 어댑터: OCR·LLM·파일·DB. 공급자 교체 가능하게 인터페이스 분리
- MCP: API와 동일한 도메인 함수를 호출
원문 추출값, AI 추론값, 사용자 수정값을 구분하여 출처를 보존합니다.

## 작업 단위
1. 이슈 작성: 사용 시나리오, 입력, 출력, 범위, 완료 기준, 필요한 자료
2. 데이터 계약 확정: Pydantic 모델, 상태, 오류, 원문 위치
3. 전문가가 판단·금액·근거가 포함된 정답 사례 작성
4. 작은 기능 구현, 대표 성공·실패·경계 사례 검증
5. 코드 검토: 자료 출처, 계산 단위, 누락 처리, 민감정보 노출 확인
6. scripts/check.sh 통과, 수동 시연, 변경 내용·제약 기록

검증 강도는 영향에 맞춥니다. 단순 스타일 변경에 형식적인 테스트를 추가하지 않습니다.
계산 변경에는 전문가 정답과 공제·한도 경계 테스트가 필요합니다.
AI가 만든 사례는 전문가 검토 전까지 정답으로 사용하지 않습니다.

## 구현 순서와 완료 기준
개인정보 보호 중심의 다음 구현은 [개인정보 보호 구현계획](PRIVACY_IMPLEMENTATION_PLAN.md)의 단계와 완료 기준을 우선 적용합니다. 아래 순서는 장기 기능 로드맵입니다.

1. 환경: 설치 재현, API 상태 응답, 웹 빌드 (이번 작업)
2. 샘플 수직 구현: 비식별 영수증·세부내역서 1쌍 → 원문 위치가 있는 항목 JSON
3. 사용자 검토: 항목 수정, 영수증 합계 대조, 불일치 표시
4. 보장 지도: 치료→가입 담보→근거 조항 연결. 정보 부족과 보상 제외 구분
5. 계산: 검토 완료 질병급여 규칙, 통원·입원 묶음, 공제·한도·반올림
6. 검증: 대표 정답 사례 일괄 실행, 금액·판단·근거 별 오류 보고
7. 확장: 비급여·정액 담보·보험증권 인식·개정 비교

## 규칙과 상태
약관 규칙: draft → reviewed → retired. 계산은 reviewed만 사용합니다.
판단: eligible / excluded / missing_information / not_enrolled / needs_review.
약관 버전·입력 스냅샷·규칙 버전·계산 단계를 기록해 결과를 재현합니다.
연간 한도 사용량이 없으면 확정액처럼 표시하지 않고 계산 가정을 명시합니다.

### 실손과 정액 급부

서류 접수·원문 근거·계약 확인·결과 화면을 공통으로 두고, 급부별로 필요한 사건과 계산 입력을 구분합니다. 실손은 진료 건의 인정 비용·공제·한도를 사용합니다. 정액 급부는 진단확정이나 사망 같은 사건, 가입 담보, 계약 상태와 약정 금액을 사용합니다. 약관 파일과 계약 유형을 식별한 뒤 해당 급부의 규칙을 선택합니다.

암 관련 진단 급부에는 진단확정일과 분류표, 보장개시일, 최초 발생과 지급 이력을 연결합니다. 종신 사망보험금에는 사망일·사망 증빙·수익자 정보와 해당 상품의 시점별 금액 기준을 연결합니다. 필수 조건이 확인되지 않으면 계산을 보류하고 부족한 입력을 표시합니다.

약관 라이브러리는 실손과 정액에 동일한 카드 틀을 사용하며 상품·문서 버전, 원문과 검토 상태를 표시합니다. 정액 초안은 가상 사례 전용 시뮬레이션에서만 실행합니다. 실제 청구 계산에 적용하려면 전문가가 검토한 규칙과 정답 사례가 필요합니다.

서류를 읽으면 실손·암·종신 검토 경로를 보여줍니다. 실손은 비용 대조와 가입 담보 확인으로 이어집니다. 암보험은 구조화한 진단서 코드와 시연 약관 분류표의 일치 여부만 표시하며, 종신보험은 사망 증빙이 필요하다고 표시합니다. 유형을 바꾸면 기존 전송 확인과 조회 결과를 지우고 등록한 서류는 세션 메모리에 유지합니다. 정액보험 검토 경로는 서버에 자료를 보내지 않습니다.

실손 시뮬레이션은 삼성화재 다이렉트 2605.1 계약전환용 질병급여 통원 1회를 다룹니다. 서류의 급여 일부본인부담액을 합산하고, 공단부담액을 포함한 비율로 공제액을 계산한 뒤 회당 한도와 보험연도 잔여 한도를 적용합니다. 연계 처방이 있고 별도 납부가 확인된 약제비는 급여 부분만 합산합니다. 병원 급여 공단부담액은 지원 서식의 급여 행 총액과 환자 부담의 차이에서 구합니다. 별도 약제비 공단부담액과 계약 조건은 사용자가 확인합니다. 원 미만 절사는 시뮬레이션의 가정이며, 규칙은 검토 전이어서 가상 사례에만 사용합니다.

## Git와 의존성
로컬 Git 저장소를 사용하며 원격 생성·업로드는 하지 않았습니다.
기능 브랜치: feat/document-extraction 같은 이름을 사용합니다.
작은 변경 단위로 커밋하고 완료 기준·검증 결과를 PR에 기록합니다.
uv.lock과 package-lock.json을 함께 관리합니다. 업데이트는 별도 작업으로 수행합니다.
CI 도입 시 scripts/check.sh와 같은 검사 및 합성 샘플만 실행합니다.

## 데이터 취급
실제 의료 서류는 data/private에만 저장하고 Git·로그에 포함하지 않습니다.
외부 서비스 전송 전 권한·보관 정책·비식별 처리를 확인합니다.
주민번호 등 계산에 불필요한 정보는 전송 전에 제거합니다.
개발 로그는 상태·요청 ID 중심으로 남깁니다.
현재 샘플 앱은 업로드나 외부 전송을 수행하지 않습니다.
