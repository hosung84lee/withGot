# 보장잇 프로젝트 목표

보장잇은 신상품 약관을 지급시스템에 등록하는 시간을 줄이고, 보험금 청구 심사자가 서류와 약관 조건을 대조하는 일을 돕는다. 두 업무는 같은 상품·약관 버전·보장ID를 사용한다.

## 1. 신상품 지급 규칙 준비

**입력**은 상품 식별자, 적용 버전이 확인된 주계약·특약 약관, 분류표와 지급기준표다. **출력**은 다음 필드를 담은 규칙 초안과 검토 의견이다.

| 필드 | 내용 |
| --- | --- |
| 보장 식별 | 상품, 약관 버전, 주계약·특약, 보장ID, 적용 기간 |
| 지급 사유 | 위험유형, 사건, 분류표, 해당 사건을 입증하는 필수 서류 |
| 특수조건 | 보장개시, 최초 1회, 감액, 면책·제외, 우선 적용·중복 조건 |
| 계산식 | 입력값, 단위, 산식, 한도, 반올림, 적용 순서 |
| 근거 및 상태 | 약관 문서·조항·페이지, 검토 상태, 승인한 규칙 버전 |

AI는 초안을 구조화하고 정의와 지급표가 충돌하는 곳, 누락된 변수, 날짜 경계와 예외 테스트를 제안한다. 담당자는 원문과 대조해 승인한다. 지급시스템에 넘길 규칙은 승인 버전으로 고정하고, 계산 엔진은 그 규칙을 사용해 같은 입력에 같은 결과를 낸다.

## 2. 보험금 청구 AI 심사 보조

진단서와 병리보고서에서 진단명, 질병분류코드, 진단확정일, 원발부위, 조직형, 병기, 침윤 여부 등 적용 약관에 필요한 사실을 추출한다. 보고서 발행일과 진단확정일은 별개 필드로 둔다. 이후 가입 계약과 승인된 약관 규칙을 대조해 보장ID별 특수조건을 평가한다.

| 태그 층 | 예시 |
| --- | --- |
| 서류에서 읽은 사실 | 진단코드 `C50.9`, 진단서 PDF 1쪽 |
| 약관 적용 결과 | 특정 버전의 일반암 분류 후보, 별표 3 |
| 조건과 다음 행동 | 최초 진단 이력 미확인, 진단확정일 및 병리 근거 확인 필요 |

태그마다 관련 서류 ID·페이지·문서 위치, 상품·약관 버전·보장ID, 적용 조항, 결과와 설명을 기록한다. 한 서류가 여러 보장에 연결될 수 있다. 상태는 `충족`, `미충족`, `정보 부족`, `서류 충돌`, `적용 대상 아님`으로 구분한다. 심사자는 원문을 보고 태그를 수락하거나 수정하며 수정 이유를 남긴다. 최종 지급 판단은 심사자가 맡는다.

### 진단내역 분류 설명 예시

| 화면 분류 | 심사자에게 보여줄 설명 |
| --- | --- |
| 초기암 확인 필요 | 적용 약관이 초기암 요건을 별도로 두는 경우, 약관이 요구하는 병기·크기·침윤 등 조건을 확인합니다. 진단서에 코드만 있어 해당 조건을 확인할 수 없습니다. |
| 소액암 후보 | 진단명 또는 분류코드가 해당 상품 약관의 소액암 분류 조건에 대응합니다. 분류표와 예외 조건을 확인해 주세요. |
| 상피내암 후보 | 서류의 진단 사실을 해당 약관의 상피내암 분류표 및 진단확정 요건과 대조해야 합니다. |
| 서류 충돌 | 진단서와 병리보고서의 판독 결과가 다릅니다. 원문 두 곳을 함께 열고 어떤 근거를 적용할지 확인해 주세요. |

상품마다 분류 기준이 달라질 수 있다. 예를 들어 라이나 무배당 건강보험 암보험 공시 약관은 별표 3에 `C50`을 포함하며, 한화생명 e암보험 상품 안내는 유방암을 소액암 범주에 표시한다. 비교 사례는 적용 계약의 실제 약관 버전을 확인한 뒤 정답 사례로 확정한다. [라이나 공시 약관 별표 3](https://www.lina.co.kr/cms/upload/upload/docs/disclosure/B00070001_0_P.pdf#page=14) · [한화생명 상품 안내](https://direct.hanwhalife.com/products/CMS00012)

## 첫 구현 범위와 측정

첫 시연은 암 진단급부 약관 한 건과 가상 진단서·병리보고서로 연결한다. 약관에서 보장 규칙과 산식 초안 생성 → 담당자 승인 → 가상 청구 판독과 증빙 태그 → 특수조건별 결과와 예상 지급액을 보여준다. 정상, 증빙 누락, 서류 충돌, 보장개시일 경계, 동일 진단의 상품별 분류 차이를 테스트한다.

- **지급시스템 등록**은 약관 접수부터 검토를 마친 규칙을 등록하기까지의 경과 시간과 담당자 작업 시간을 기존 방식과 비교한다. 필드별 일치율과 수동 수정 건수를 함께 기록한다.
- **심사 보조**는 서류가 준비된 시점부터 심사자가 결론을 기록할 때까지의 시간, 태그 정확도, 정보 부족·서류 충돌 탐지율과 잘못 충족 처리한 사례 수를 측정한다.
