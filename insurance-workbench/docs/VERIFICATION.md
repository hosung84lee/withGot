# 검증 결과

## 실손 질병급여 통원 계산 (2026-11-07)

- 금융위원회 공개 계산 예시의 급여 본인부담금 200,000원과 공단부담금 300,000원에서 공제액 80,000원, 한도 적용 전 120,000원을 재현했다. 회당 한도, 연간 잔여 한도와 원 미만 절사도 확인했다.
- 기본 가상 사례에서 병·의원을 선택하고 한도가 충분할 때 8,150원이 표시됐다. 조회용 체크박스를 해제해도 통원 전체의 급여 비용을 사용했다. 공제 후 0원, 잔여 한도 소진, 보장 제외와 계산 보류를 구분했다.
- 별도 납부한 급여 약제비는 공단부담금이 확인되면 합산했다. 이미 포함된 영수증은 재합산하지 않았다. 계산 과정에서 서버 전송은 발생하지 않았다.
- 개발 서버 웹 테스트 33개, 빌드 미리보기 신규 테스트 3개, API 테스트 23개와 TypeScript·Vite 빌드를 통과했다.

## 보험별 청구 검토와 정액 시뮬레이션 (2026-11-07)

- 실손과 정액의 카드에서 상품과 버전, 검토 기준, 자료 상태와 원문 위치를 확인했다. 모바일 390px에서 약관, 기본 서류와 보험 선택 카드의 줄바꿈을 점검했다.
- 기본 PDF를 역순으로 선택해도 서류 유형과 원본이 정확히 연결됐다. [가상 C44.9 진단서](../data/synthetic/claim-routing/c44-diagnosis.pdf)와 [가상 C50.9 진단서](../data/synthetic/claim-routing/c50-diagnosis.pdf)는 각각 기타피부암과 일반암 분류 후보를 표시했다. 코드가 미지원인 진단서에는 분류 확인을 안내했다. 첨부를 제거하면 해당 후보가 사라졌다.
- 암·종신 검토로 변경하면 앞서 작성한 실손 전송 확인이 지워졌고, 서류는 세션에 유지됐다. 선택 변경과 자료 읽기 중 POST 요청은 발생하지 않았다.
- 가상 정액 사례 20개로 암 대기·감액 경계와 진단 분류, 종신 체증 경계와 상한, 세 가지 지급 기준의 선택 및 증빙 부족 시 보류를 확인했다. 가상 규칙은 실제 청구 계산에 사용하지 않는다.
- API 테스트 23개와 개발·빌드 미리보기의 웹 회귀 테스트 각 30개를 통과했다. 카드의 최종 배치를 적용한 뒤 TypeScript·Vite 빌드와 해당 화면의 브라우저 테스트 6개를 두 환경에서 다시 확인했다.

## 첨부 서류 목록과 샘플 다운로드 (2026-11-07)

- 첫 화면에서 기본 서류 2종과 추가 서류 4종의 개별 샘플 링크를 확인했다. 추가 서류 링크 네 개 모두 유효한 PDF를 반환했다. 내려받은 진단서를 다시 첨부해 구조화 결과와 첨부 건수를 확인했다.
- 웹 빌드와 개발 서버 웹 테스트 24건이 통과했다. 빌드 미리보기에서는 추가 서류 테스트 4건이 통과했다.

## 추가 서류와 계산 기초자료 (2026-11-07)

- 가상 진단서·처방전·납입확인서·약제비 영수증을 앱에서 읽고 구조화 값과 원문 줄·페이지를 확인했다.
- 병원 환자 부담액 563,150원과 약국 환자 부담액 12,400원은 처방번호 연결과 별도 납부 확인 후 575,550원으로 대조됐다. 병원 진료비에 포함된 약제비와 병원 납입확인서는 추가 합산에서 제외됐다.
- 중복 문서와 다른 사례를 거절했다. 같은 처방의 영수증 중복 가능성, 납입액 불일치, 처방전 제거 시 비용 합계가 보류됐다. 실제 보장 후보 조회 요청에 추가 서류 데이터가 들어가지 않았다.
- 웹 빌드와 API 테스트 23건, 개발 서버 웹 테스트 전체 23건, 빌드 미리보기의 추가 서류 테스트 3건이 통과했다.

## 진료비 서류 샘플 추가 검증 (2026-11-07)

- [합성 PDF 세 쌍](../data/synthetic/medical-bills/README.md)을 추가하고 모든 페이지를 렌더링했다. 급여 외래 정상 조회, 여러 페이지 원본 위치, 합계 불일치와 수정 후 재검토, 서로 다른 사례번호 거절을 확인했다.
- 웹 테스트 전체 20건이 개발 서버에서 통과했다. 추가 서류 테스트 4건은 빌드 미리보기에서도 통과했다.
- [공개 빈 서식](../data/reference/README.md)의 PDF 두 개를 실제로 선택했다. 공식 영수증은 미지원 서식으로, 이미지형 세부내역서는 텍스트 없음으로 안내했으며 조회 요청은 0건이었다. 공식 세부내역서 앞뒷면은 표 구조를 확인하는 참고 원본으로 보관했다.

## 심사 시연의 결과 근거와 전송 내역 (2026-11-07)

- 가상 샘플을 조회하고 혈액 검사와 복부 MRI를 선택해 급여 구분의 출처, 가상 담보 상태, 원본 페이지, 다음 확인 항목을 대조했다. 수정한 값이 표시되어도 원본 강조는 원래 줄을 가리켰다.
- 전송 확인 화면을 닫은 뒤 결과에서 다시 연 전송 내역이 실제 성공한 HTTP 요청 본문과 일치했다. 해당 요청에 가상 환자번호·이름·파일명·진료비가 포함되지 않았다. 항목을 변경하면 이전 결과와 전송 내역이 정리됐다.
- 급여 구분 미확인 항목은 적용 담보를 검토 중으로 표시했다. 모바일 너비 390px에서 전송 내역을 열어도 페이지가 가로로 넘치지 않았다.
- Ruff·pytest 23건·TypeScript·Vite 빌드 통과. 웹 테스트 16건은 개발 서버와 빌드 미리보기에서 각각 통과했다.

## 분석 시작 편의 개선 (2026-11-07)

- 가상 샘플을 불러오지 못한 뒤 재시도하면 사용자 다운로드 조작 없이 두 정적 PDF를 읽고 검토 화면으로 이동했다. 이 과정에서 조회 요청이나 문서 데이터 전송은 없었다.
- 직접 선택한 첫 PDF를 대기 목록에 유지했다. 두 번째 파일이 잘못됐을 때 해당 파일만 빼고 교체해 정상 검토로 진행했다.
- 샘플 불러오기 중 초기화한 뒤 이전 선택이 나타나지 않았고, 정상 파일을 다시 읽을 수 있었다.
- Ruff·pytest 23건·TypeScript·Vite 빌드 통과. 웹 테스트 15건은 개발 서버와 빌드 미리보기에서 각각 통과했다.

## 조회 데이터 최소화와 화면 이동 (2026-11-07)

- 실제 브라우저 요청에서 진료비 총액·환자 부담액과 조회에 관계없는 담보 상태가 제외되는지 확인했다. 급여 구분이 미확인인 항목은 담보 상태 없이 조회했다.
- 새 요청 형식과 기존 금액 포함 요청이 같은 가상 보장 후보를 반환하는지 확인했다. 조회에 필요한 담보 상태가 누락되면 API가 요청을 거절했다.
- 전송 확인, 조회 결과, 원본 위치 열기에서 해당 영역의 제목으로 초점이 이동했다.
- Ruff·pytest 23건·TypeScript·Vite 빌드 통과. 웹 테스트 12건은 개발 서버와 빌드 미리보기에서 각각 통과했다.

## 추가 시나리오 및 회귀 검증 (2026-11-07)

[테스트 시나리오 12개](TEST_SCENARIOS.md)를 기준으로 API 21건, 웹 11건을 실행했다. 웹 테스트는 개발 서버와 빌드 미리보기에서 각각 모두 통과했다. Ruff와 TypeScript·Vite 빌드도 통과했다.

- 조회 주소 끝에 슬래시가 있는 요청은 리디렉션 없이 404로 처리한다. 실제 서버의 응답 헤더와 표준 출력·오류 로그에서 가상 환자번호가 다시 나타나지 않았다.
- 급여 구분이 미확인이면 특약 가입 상태만으로 판정하지 않고 적용 가능한 담보를 확인하도록 안내한다.
- 영수증과 세부내역서 역할을 동시에 선언한 문서는 거절한다.
- 조회에 실패한 뒤 같은 전송 내용으로 재시도하면, 성공 결과의 첫 선택과 원본 강조 행이 일치한다.
- 암호화 PDF를 기기에서 거절한 뒤 정상 파일을 역순으로 선택해 복구할 수 있었으며, 이 과정에서 조회 요청이 발생하지 않았다.

## 개인정보 보호 시연 구현 (2026-11-07)

- Windows에서 웹 잠금 파일 기준 설치, Ruff, pytest 17건, TypeScript 검사와 Vite 빌드 통과. npm 설치 감사에서 취약점 0건 확인.
- Chrome에서 Vite 개발 서버와 빌드 미리보기 각각 개인정보 보호 테스트 6건 통과.
- 가상 PDF 선택·검토 중 문서 데이터 전송이 발생하지 않았고, 명시적 조회 요청의 본문은 화면의 전송 스냅샷과 일치했다. 수정값과 원문 위치를 구분하여 표시했다.
- 전송 검토 초기화, 합계 불일치 차단, 요청 실패·재시도, 중복 조회 방지, 진행 중 초기화를 검증했다.
- 파일 크기·페이지 수·텍스트 유무·손상·미지원 서식 제한을 검증했다. 테스트 PDF의 문서 스크립트 실행과 제3자 요청은 관찰되지 않았다.
- 세션 초기화 뒤 미리보기 URL이 해제되고 앱의 브라우저 저장소가 비어 있음을 확인했다.
- 가상 환자번호를 추가 필드로 보낸 실제 API 요청은 HTTP 422로 거절됐다. 응답과 API 표준 출력·오류 로그에 해당 문자열이 남지 않았다.

검증 범위는 가상 자료와 synthetic-v1 규칙이다. 실제 의료 서식의 추출 정확도, 실제 보험 판정, 공개 배포 환경의 보호 설정은 별도 검증 대상이다.

## 초기 환경 확인

- Python 3.12.14 / Node.js 24.22.1 / npm 11.9.0
- uv sync 완료: uv.lock 생성, 프로젝트 .venv 사용
- npm install 완료: package-lock.json 생성
- Ruff 검사 통과
- API 상태 테스트 1건 통과
- TypeScript 검사·Vite 빌드 통과
- 웹·API·Vite 프록시 HTTP 200 확인
- MCP 상태 도구 호출 성공 (호환성을 위해 SDK 1.x로 제한)

관리형 환경에서는 네트워크 권한이 없는 셸에서 TestClient 검사가 멈출 수 있습니다.
테스트 실행에는 로컬 통신이 허용되는 실행 환경을 사용합니다.
실제 의료비·약관 판단 정확도를 검증한 결과가 아니며 해당 기능은 아직 구현 전입니다.
