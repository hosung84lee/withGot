# 보장 JSON 스키마 보완 (샘플 약관 7개 분석, 2026-11-11)

목표: **약관 → 미리 정의한 스키마(`src/schema/json/coverage.json`)로 보장을 뽑아내기.**
초안(PR #5)의 필드 이름·구조는 그대로 두고, 샘플 약관 7개에 실제로 나오는데 초안에 없던 것을 추가했다.
초안은 properties 목록만 있던 것을 표준 JSON Schema(draft 2020-12)로 감싸서 `jsonschema` 로 검증할 수 있게 했다.

- 스키마: [`src/schema/json/coverage.json`](../src/schema/json/coverage.json) (보장 하나의 모양)
- 초안 예시(그대로 통과): [`cov_sample.json`](../src/schema/json/cov_sample.json) — 인터넷암 2404 소액암 2건
- 7개 약관 예시: [`cov_samples_7policies.json`](../src/schema/json/cov_samples_7policies.json) — 원문에서 손으로 옮긴 12건
  (`uv run python tools/schema_samples/build.py` 로 다시 만들고 검증)
- 코드: [`src/coverage_json/`](../src/coverage_json/) — 검증, KCD 범위→정규식, 기존 사고보장 데이터→스키마 변환, AI 스키마 추출, 두 약관 비교
- 화면: 약관 분석 → 「약관 비교 (스키마)」 탭

## 3. 아직 열어 둔 것

- **보장 단위**: 지급 조건이 같은 보험금을 한 보장으로 묶을지(2404 암진단Ⅰ·Ⅱ·Ⅲ), 나눌지(초안 예시는 소액암 24%/12% 를 나눔). 예시는 둘 다 있음 — 팀 규칙으로 정할 것.
- **분류질병 판정**: 초기유방암(C50 중 TNM 1기)·중증 갑상선암(조직형)처럼 코드로 못 가르는 것은 `ai_review_items` 로만 둠.
- **실손 세대**: 약관에 세대 표기가 없어 '판단불가' 가 많음. 판매 시기 기준표가 필요.
- **연금·체증 계산값**: 산출방법서에 있어 약관만으로는 금액을 못 정함 (`amount_type: 연금산출`).
- **제도특약**: 보장 항목을 만들지 않음. 필요하면 `policy_kind` 만 남기는 빈 항목 규칙을 정할 것.

## 4. 약관 비교 탭

약관 분석 → 「약관 비교 (스키마)」: 약관 2개를 골라 각각 스키마 JSON 으로 만든 뒤, 보장끼리 짝(청구사유 + 이름 유사도 +
보장종목 + KCD 겹침)을 맞춰 필드별로 나란히 보여 줌. 다른 필드는 ❗.

- **AI 스키마 추출(OpenAI)** 을 켜면: 보장 묶음마다 조문 + 그 약관의 보험금 지급기준표(별표)를 넣고 스키마를 보여 준 뒤 JSON 을 받음.
  `jsonschema` 로 검사해 틀리면 오류를 알려 다시 받고(2번), 그래도 틀리면 맞는 항목만 남김. 묶음 동시 처리, 결과는
  `src/data/cache/schema/<파일 해시>/` 에 캐시.
- 끄면(API 없음): 정답 데이터·이전 사고보장 추출 결과(`schema.coverage.Product`)를 스키마로 변환해서 비교.
  지금 데이터가 있는 약관은 실손 2605(정답 + AI 6묶음), 인터넷암 2404(정답 초안)뿐이라 나머지는 AI 추출이 필요.
