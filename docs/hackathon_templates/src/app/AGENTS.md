# src/app — Streamlit UI 규칙 (앱 담당)

## 구조
- `main.py` 는 페이지 이동과 공통 레이아웃만 담당한다. 화면은 `views/` 에 한 화면당 한 파일로 둔다.
- 화면: 약관 구조화 / 사고보장 데이터·근거·갭 검토 / 청구 시나리오·계산 / 검토·승인

## 규칙
1. 워크플로는 `workflow.policy`, `workflow.claim` 의 공개 함수만 호출한다. `agent/`, `mcp_server/`, `skills/` 를 직접 import 하지 말 것.
2. 앱에서 LLM 호출, 판정 로직, 금액 계산 금지. 받은 결과를 보여주기만 한다.
3. 워크플로가 아직 없으면 `src/data/mock/*.json` 으로 화면을 먼저 완성하고, 나중에 공개 함수 호출로 바꾼다. mock 형식은 `src/schema/` 모델과 같아야 한다.
4. 세션 상태는 `st.session_state` 만 쓰고, 키 이름은 `policy.*`, `claim.*`, `review.*` 로 나눈다.
5. 오래 걸리는 작업은 워크플로의 `on_progress` 콜백을 받아 `st.status` 로 단계별 진행 상황을 보여준다.
6. **검토·승인 UI 가 핵심이다.** AI 결과마다 근거(약관 조·항·별표 원문, 서류)를 나란히 보여주고 승인 / 수정 / 반려를 제공한다. 결정은 `backend/` 를 통해 저장한다.
7. AI 판단 결과는 결과·근거·소스를 항상 함께 보여준다. `escalations`(스키마에 없는 항목)와 근거 검증 `needs_review` 는 별도 영역에 눈에 띄게 표시한다.
8. 색 규칙: 승인·지급 = 초록, 반려·부지급 = 빨강, 검토 필요·에스컬레이션 = 주황.
9. 금액은 천 단위 구분 기호로 표시한다.

## backend
- DB 접근과 SQL 은 `src/backend/` 에만 둔다. 화면 코드에 SQL 을 쓰지 말 것.
- 업로드 파일은 `backend` 의 저장 함수로 `src/data/` 아래에 저장하고, 화면에는 경로만 넘긴다.
