# src/workflow — 처리 파이프라인 규칙

- `policy/`(흐름 1)는 약관 담당, `claim/`(흐름 2)은 보험금 담당이다. 상대 폴더는 수정하지 말 것.

## 규칙
1. 각 step 은 Pydantic 입력을 받아 Pydantic 출력을 내는 함수로 만든다.
2. 앱이 부르는 공개 함수는 각 하위 패키지의 `__init__.py` 에서만 내보낸다. 시그니처를 바꾸기 전에 앱 담당의 확인을 받을 것.
3. 공개 함수는 `on_progress(step: str, message: str)` 콜백을 인자로 받는다. **workflow 에서 streamlit 을 import 하지 말 것.**
4. step 마다 산출물을 저장해서 단계별로 다시 실행할 수 있게 한다. 사람이 검토·수정한 결과를 받아 다음 step 을 이어서 실행할 수 있어야 한다.
5. LLM 호출은 `agent/` 의 함수로만, 계산은 계산 툴로만 한다. 규칙으로 할 수 있는 일(구조화, 근거 검증, 갭 분석)은 workflow 의 코드로 한다.
6. 서로 독립적인 작업(묶음별 추출, 판단 항목별 판단)은 `asyncio.gather` 로 병렬 실행한다.

## 흐름 1 (policy) step — 설계·규칙·정답 수치는 docs/REBUILD_GUIDE.md
텍스트 추출 → 구조화(규칙) → 구조 검증 → 추출 묶음(규칙) → LLM 추출(① ② ③) → 근거 검증(규칙) → 갭 분석(규칙)

## 흐름 2 (claim) step
청구정보(④) 입력 → 보장 매칭(KCD·사건 유형) → 계산 툴 호출 → AI 판단 항목 위임 → 심사자 검토용 결과(⑤) 정리
